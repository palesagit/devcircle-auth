## What the app does
| Feature | Details |
|---|---|
| **Sign up** | Username, email, password; choose *Student* or *Personal* email (Firebase Authentication). |
| **Log in / log out** | Friendly errors: wrong password, no internet, too many attempts. |
| **Forgot password** | "Forgot password?" emails a reset link; the user opens it and creates a new password. Logged-in users can use the settings icon, then *Change password*. |
| **Shared chat** | Circles, topics, messages, resources and meetings are stored in **Cloud Firestore**. Everyone sees the same data and new messages appear instantly. |
| **Chat history** | A new user sees every earlier message. The newest 100 load first; "Load older messages" loads more. |
| **Unread badges** | Pink badge shows how many messages you haven't opened yet. |
| **Push notifications (FCM)** | Asks permission, saves the device token, shows a banner for messages that arrive while the app is open, and has a background handler. |
| **Security rules** | Profiles are private; only signed-in users can read chat data; every message carries the sender's own id; nobody can edit or delete other people's messages. |
| **Starts empty** | No sample data and no pre-made accounts. The first users create everything. |

## How the data is stored (Cloud Firestore)
```
users/{uid}                       username, emailType, fcmToken
users/{uid}/reads/{circle_topic}  how many messages this user has seen
circles/{circleId}                name, tag
  topics/{topicId}                name, messageCount, lastMessageAt
    messages/{messageId}          text, senderId, senderName, createdAt
  resources/{id}                  title, link, createdByName
  meetings/{id}                   topic, link, when
```

## One-time setup

**1. Tools** (Flutter: https://docs.flutter.dev/get-started · Node.js: https://nodejs.org)
```bash
npm install -g firebase-tools
dart pub global activate flutterfire_cli
```

**2. Firebase console** (console.firebase.google.com)
1. Create a project.
2. **Authentication** -> Sign-in method -> enable **Email/Password**.
3. **Firestore Database** -> Create database.
4. Firestore -> **Rules** tab -> paste the contents of `firestore.rules` -> **Publish**.

**3. Get the code and connect it to your Firebase project**
```bash
git clone https://github.com/<your-github-username>/devcircle-auth.git
cd devcircle-auth
flutter create --project-name devcircle_auth .   # creates android/web folders if missing
flutter pub get
firebase login
flutterfire configure                            # choose your project; tick android + web
```

### Verify shared chat history with two users

Keep both app instances running. Use a regular browser window for `user1` and a private/incognito window for `user2` so each user has a separate sign-in session.

1. In **Terminal A**, start the app in Chrome:
   ```bash
   flutter run -d chrome
   ```
   In **Window A**, sign up as `user1`, create the `general` topic, and send exactly 3 messages. Leave this window signed in and open.
2. Open a **second terminal** in the project directory. In **Terminal B**, start another app instance:
   ```bash
   flutter run -d web-server --web-port 8081
   ```
   Leave this command running. If port `8081` is already in use, use the existing server rather than starting another one.
3. Open a private/incognito browser window and go to [http://localhost:8081](http://localhost:8081). In **Window B**, sign up as `user2` with a different email address.
4. Confirm `general` appears with a pink unread badge showing **3**. Open it and verify all 3 earlier messages are visible in the history.

For a remote second user, open the deployed web app in a separate browser profile or private window instead. For Android: run `flutter devices`, then `flutter run -d <device-id>`.

**Deploy to the web (free)**
```bash
flutter build web --release
firebase init hosting            # public directory: build/web · single-page app: Yes
firebase deploy --only hosting   # prints your https://....web.app link
```

**Build the Android app**
```bash
flutter build apk --release      # build/app/outputs/flutter-apk/app-release.apk
```

## Demo script (about 4 minutes)
1. Run `flutter run -d chrome`. **Window A** opens on the **Sign up** screen (nobody is logged in).
2. **Sign up** as `user1` (student email). The app is **empty**: no topics, resources or meetings.
3. Click **+** next to TOPICS, create `general`, send 3 messages. Add a resource and a meeting.
4. **Window B** (private window / second device): sign up as `user2`.
5. User 2 sees `general` with a **pink badge (3)**. Open it: **the full history is there**. Reply.
6. Back in Window A, the reply appears **instantly**.
7. **Forgot password:** log out (settings icon -> Log out), click **Log in** -> **Forgot password?**, enter the email, show the reset email, set a new password, log in with it.
8. Show **Firebase console**: Authentication -> Users, and Firestore -> `circles/devcircle/topics/general/messages`.
9. Run `flutter test` and show the tests pass.

## Limits (honest notes)
- Push notifications are sent from the Firebase console. Sending one automatically for every new message needs Cloud Functions (not included).
- No moderation yet (no edit or delete), and the student-email choice is not verified.
- Windows and Linux desktop are not supported by this Firebase setup. Use the web version there.
- Firebase's free plan has daily read/write limits.
